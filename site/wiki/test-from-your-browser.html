    From your own browser

    Run your packaged Windows app and Epic's signalling server on one machine, and stream it to a browser tab on that same machine.

    Before you start

    A packaged Windows build with the Pixel Streaming plugin enabled. If you want a build known to be good to compare against, the demo app on this page's source has already passed the upload sequence.

    Step 1. Check the build runs at all

    Double-click the .exe. It should open as an ordinary desktop application.

    If it does not launch here, stop. A build that will not run as a desktop app is not a valid package, and no amount of Pixel Streaming configuration will make it stream. Fix the packaging first.

    Step 2. Fetch the signalling server

    Epic's servers are not in the package by default — a script downloads them. Find it under your packaged build: 

    <Packaged Folder>\Windows\<YourProject>\Samples\PixelStreaming\WebServers\get_ps_servers.bat

    Run it. A terminal opens, files download, and it closes itself when finished.

    Step 3. Start the signalling server

    <Packaged Folder>\Windows\<YourProject>\Samples\PixelStreaming\WebServers\SignalingWebServer\platform_scripts\cmd\run_local.bat

    On newer Unreal versions this file is called Start.bat. Same folder, same job — if run_local.bat is not there, that is what you are looking for.

    Leave that terminal open for the rest of this guide.

    Step 4. Launch the app with streaming arguments

    The app needs to be told to stream rather than open a window. Make a shortcut to the .exe, open its Properties, and append this to the end of the Target field, after a space: 

    -log -AudioMixer -PixelStreamingIP=localhost -PixelStreamingPort=8888 -RenderOffScreen -AllowPixelStreamingCommands

    So the whole field reads something like:

    "C:\...\MyProject2\Packaged Folder\Windows\MyProject2.exe" -log -AudioMixer -PixelStreamingIP=localhost -PixelStreamingPort=8888 -RenderOffScreen -AllowPixelStreamingCommands

    Click OK, then run the shortcut — not the original .exe. Leave its terminal open too.

    Step 5. Open it in a browser

    Go to localhost or 127.0.0.1 and press CLICK TO START.

    You should see your app, and it should respond to input

    That is the same thing the platform checks when you upload. If it works here, the build itself is not the reason an upload fails.

    If the page loads but the app never appears

    This is what a build without Pixel Streaming looks like. The server is fine; nothing connected to it. Enable the plugin, repackage, and try again — and note that this is exactly the failure that produces the yellow warning at phase 1 of an upload.
