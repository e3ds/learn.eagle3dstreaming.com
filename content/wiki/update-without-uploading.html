Replace an application's files directly on your own streamer machine, without uploading a new build to the Control Panel. The app entry, the configuration and the streaming URL all stay as they are.

This exists for one reason above all others: the build never leaves your machine. If your application cannot be uploaded — because of a security policy, a customer contract, or content you are not allowed to transfer — this is how you stream it anyway.

It is not a shortcut for ordinary updates. Uploading through the Control Panel is simpler, is versioned, and works across every machine. Do that unless you have a reason not to.

Before you begin

  • The E3DS Streaming Agent installed on the machine that will host the app.
  • An application already uploaded to the Control Panel — see the first step, which explains why.
  • Your packaged build, ready to copy.

Set it up once

  1. Upload an application, using the name you will actually use

    The Control Panel entry is what creates the app record, its configuration and the local directory the agent later uses. Something has to be uploaded first.

    If you cannot upload the real build, upload a small placeholder — but give it the real name. The agent builds the local directory path from the application name, so a placeholder called Test produces a directory your real app will not be found in. If the app is MyApp, the placeholder is MyApp.

  2. Install and configure the streaming agent

    On the machine that will host the application — see stream from your own hardware.

  3. Stream it once

    This is not optional and it is easy to skip. The first stream is what makes the agent download the app and create the local directory structure. Until that has happened there is nothing on disk to replace.

Replace the build

Everything below happens in one directory:

C:\e3ds_streaming_apps\<username>\<application-name>\1

For a user mwoji with an app called MyApp, that is C:\e3ds_streaming_apps\mwoji\MyApp\1. The trailing 1 is the version directory.

  1. Back up what is there

    Copy the directory somewhere else first. If the new build does not run, this is the only way back — there is no upload history to fall back on, which is the trade you accepted by not uploading.

  2. Delete the old files, but keep .meta

    Remove the application files from the version directory and leave the .meta folder alone. The agent created it and uses it to recognise the app; deleting it means the agent no longer knows what is in this directory.

  3. Copy your new build in

    The whole packaged application — every folder and file, not just the executable. Paste it into the same version directory.

  4. Make the executable name match the original

    If the original was MyApp.exe, the new one must also be MyApp.exe. Rename it if your build produced something else. The agent launches the name it was configured with, and a mismatch means it finds nothing to start.

You will know it worked when

Opening the same streaming URL as before starts a session running your new build. Nothing about the link, the app entry or the configuration changes — only what is on the disk.

Doing it again

Later updates are the same four steps, without the setup: stop any active session, back up the version directory, remove the old files while keeping .meta, copy the new build in with the same executable name.

Every machine is updated by hand. This replaces files on one machine. If you run several streamer machines, each one needs the same treatment, and a machine you forget will keep serving the old build to whoever happens to land on it.
