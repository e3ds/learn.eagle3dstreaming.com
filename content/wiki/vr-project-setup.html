Create a VR project, configure it for streaming, fix the two problems the Unreal template ships with, and package it ready to upload.

Before you begin

  • Unreal Engine 5.5. Not another version — see why.
  • Visual Studio configured for Unreal. Packaging fails without it, and the failure does not say so clearly.
  • A headset for testing. We have verified Quest 2 and Quest 3.

Create the project

In Unreal Editor, create a new project, choose Virtual Reality under Games, name it and press Create.

Configure the plugins

One plugin goes on and one goes off. Pixel Streaming is enabled; OpenXR is disabled. Disabling OpenXR in a VR project reads like a mistake, which is why it is the step people skip. Streaming will not work correctly with it left on.

  1. Open Edit › Plugins

  2. Search "Pixel Streaming" and enable it

  3. Search "OpenXR" and disable it

  4. Restart, then dismiss the popup that follows

Clean up the template

Two things in Unreal's VR template need attention before it will stream properly.

  1. Delete B_Asset Guideline from the Content Drawer

    It is a guide asset for people working in the editor, and has no place in a streamed build.

  2. Open VRPawn, then compile and save

Fix the player spawning in the floor

The template's player starts partly below the ground, and returns there after every teleport. The cause is worth knowing, because it explains why moving the Player Start is the fix: teleportation moves the centre of the player to the target, without accounting for the collision capsule — so the lower half of the capsule ends up inside the floor.

  1. Raise the Player Start along Z

    Select the Player Start actor in your level and move it up until the collision capsule clears the ground. In the stock template about +110 units is enough. Aim for standing on the ground — neither sunk into it nor floating above it.

  2. Check the warning has gone

    Unreal draws a red Bad Size label on a Player Start whose capsule is obstructed. When your offset is right, that label disappears — which makes this the rare fix you can confirm without launching anything.

The Player Start shows the capsule of your game mode's default pawn class, not of whatever pawn you happen to have selected. If the warning behaves strangely, check that the game mode names the pawn you actually spawn.

Package it

  1. Platforms › Windows › Package Project

    Choose an empty folder for the output.

  2. Watch the output if it fails

    Press Show Output Logs. The most common cause of a packaging failure is Visual Studio not being configured for Unreal, which the log will say and the dialog will not.

  3. Zip the contents of the Windows folder

    Select everything inside it and compress that — not the folder itself, which buries the .exe a level too deep.

You now have

A ZIP ready to upload. Test it locally with a headset first, then upload it exactly like any other application.
