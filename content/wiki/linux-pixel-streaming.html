Stream a Linux build of your Unreal project. The path is the same as for Windows — build, upload, stream — with a cross-compile toolchain at the start and one configuration setting that must be right.

There is a live example: the Linux demo app. If you want to try the upload without building anything first, download the sample ZIP and use that.

Read this before you start

Two limitations, stated plainly, because both are much easier to plan around than to discover.

We do not check whether your Linux build has Pixel Streaming enabled. Windows uploads are stream-tested; Linux uploads are not. A build with the plugin missing uploads successfully, looks correct in the Control Panel, and fails only when somebody opens the stream. Verify the plugin before packaging — nothing downstream will catch it for you.

Linux streams start more slowly than Windows ones. That is infrastructure, not your build: demand for Linux streaming is low, so those machines are not kept warm the way the Windows fleet is. Every session allocates a machine, starts it, downloads your app and then launches it — and you wait for all four.

If start time matters for your use — a demo to a client, an event with an audience already waiting — talk to support beforehand. There are things we can do, but not at short notice.

One more: Linux builds in VR are untested. Not known to be broken — simply never verified. Treat it as unsupported rather than as likely to work.

The path

  1. Install the cross-compile toolchain, then package

    You build the Linux version from Windows, using Unreal's cross-compile toolchain. Build a Linux package covers installing it and producing the build.

  2. Set the platform in your configuration

    The step that is easiest to miss and hardest to diagnose: a Linux app whose configuration still says Windows waits in the queue for a machine that will never match it.

  3. Upload and stream

    The same Control Panel as any other app, with one naming rule specific to Linux. Upload and stream a Linux build.
