Move files in both directions: hand the viewer a file your app produced, or let them upload one into the app's own directory.

Sending a file to the viewer

Any file that exists in your project's directory on the streaming machine can be downloaded by the viewer — a generated PDF, an exported model, a saved configuration.

  1. Place an E3DS_PS_actor in the level.

  2. In the Level Blueprint, add your trigger (the demo uses the H key).

  3. Add a Get Project File Path node with the path to the file, feed it into Construct PS Message To Download A File from Unreal App Directory To User's Device, and feed that into Download A File From Unreal App Directory To User's Device. Compile and save.

What you should see

Press the key with the viewport focused and the browser downloads the file. Nothing happening almost always means the path is wrong — the file must exist on the machine running your app, not on yours.

Receiving a file from the viewer

The platform opens the browser's file picker, takes what the viewer chooses, and writes it into your project directory. Your app then reads it as an ordinary file.

  1. Call Transfer File from User Browser to Unreal and give it a destination inside the project — for example ProjectDirectory/Saved/.

  2. The viewer picks a file in the dialog the platform opens.

The destination must be inside the project directory. Absolute paths such as C:\ and any folder outside the project are not supported. Uploaded files are also virus-scanned, and anything flagged is rejected rather than delivered.

Knowing when the upload is done

Uploading is not instant, so the platform reports progress as messages your app can listen for.

MessageMeans
onUserSideFileSelectedThe viewer picked a file. The upload has started.
onUserSideFileProcessingFinishedThe browser has finished sending it.
onUploadedFileAvailableThe file is now in your project directory. This is the one that means success.
onUserSideFileSelectionCanceledThe viewer opened the dialog and closed it without choosing.

Each carries the filename, except the cancellation. Together they give you the three states worth tracking: in progress, finished, abandoned.

Handle the cancellation, not just the success

A common pattern is a timer that polls for the file with File Exists until it appears. That works — until somebody closes the dialog, and the timer waits forever for a file that will never arrive. onUserSideFileSelectionCanceled is what stops it.

Without the plugin

Send this with Send Pixel Streaming Response:

{"cmd": "sendLocalFileToUE4", "pathToSaveFile": "%AnyPathInsideProjectDirectory%"}
