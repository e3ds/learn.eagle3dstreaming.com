One endpoint that tells you whether the Pixel Streaming service is operational — for a status indicator in your own product, or for uptime monitoring.

Request

POST https://agw.eagle3dstreaming.com/api/v4/health-check
Content-Type: application/json
{
  "apiKey": "your Eagle 3D Streaming API key"
}

Response

Healthy:

{
  "status": "ok",
  "checks": { "connector": "healthy" },
  "timestamp": "2026-04-24T04:32:40.168Z",
  "version": "1.0.0"
}

Not healthy:

{
  "status": "unhealthy",
  "checks": { "connector": "unhealthy" },
  "timestamp": "2026-04-24T06:44:20.479Z",
  "message": "One or more health checks failed"
}
FieldTypeWhat it is
statusstringok, unhealthy, or error.
checks.connectorstringThe streaming connector: healthy or unhealthy.
timestampstringUTC time of the response.
versionstringAPI version. Only present on success.
messagestringDetail. Only present when unhealthy.

The three statuses are not two

error is about your request, not our service

ok means the service is up and unhealthy means it is not — but error means the call itself failed authentication or validation. A status page that treats error as an outage will report us down when the real problem is a key that expired on your side.

The two failure shapes look like this:

{
  "error": "Invalid API Key",
  "status": 401,
  "meta": { "error": { "message": "illegal argument" }, "status": 403 }
}
{
  "status": "error",
  "code": "MISSING_API_KEY",
  "message": "API key is required and must be non-empty",
  "timestamp": "2026-04-24T04:38:06.038Z"
}

What to use it for

  • A live service-status indicator in your own application.
  • Telling a viewer why a stream will not start, instead of letting them wait.
  • Feeding an uptime monitor or an internal dashboard.
