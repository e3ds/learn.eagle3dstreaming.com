Who can open your stream, and when it stops. Five settings, three of which are time limits that sound alike and do different things.

All of them live in Edit Config for a stream link, so they apply per configuration rather than per app — one app can have a locked-down link for customers and an open one for your own testing.

The three time limits

SettingLimitsEnds a session that is
Link expiration How long the link works Not running — it stops new sessions starting
Max session time How long one session may run Running, however busy the viewer is
Logout after inactivity How long a session may sit idle Running but untouched

A link that has expired cannot start anything. A session at its maximum ends even if someone is actively using it. An idle timeout ends a session nobody is touching — which is the one that catches the tab left open over lunch.

With all three disabled, a session runs until something stops it. There is no platform-imposed maximum — ten hours, fifty hours, longer, as long as your subscription has minutes and the connection holds. On a prepaid-minute plan that is a bill for time nobody was watching.

Set at least the idle timeout. It costs a real viewer nothing, and it is the only one that distinguishes "still being used" from "still open".

If a stream ends unexpectedly, check these before assuming a fault. A session hitting its maximum and an application crashing look identical from the viewer's side. Rule out the setting you configured before investigating the app.

Password protection

With Password Protect Stream enabled, a viewer must enter the password before the application will load. The link alone is not enough.

Set it on the configuration behind the link you share. Anyone with the link and the password gets in, so it protects against a link being forwarded, not against a password being forwarded — for per-person access, put a login in front of it instead.

Anonymising the URL

By default a streaming URL contains your username, the app name and the configuration name. Anonymize URL replaces that structure with an opaque one.

Worth doing when the URL would otherwise tell a customer things you would rather it did not — an internal project name, how many configurations you keep, or simply that the app is called ClientName_Pitch_v3. It does not restrict access; it stops the address itself being informative.

Choosing between them

Anonymise to hide what the link says. Password to stop a forwarded link working. Expiry to stop it working after a date. They are independent, and a shared demo link usually wants all three.
