A Convai project expects a microphone attached to the machine it runs on. In a streamed app there isn't one — the microphone is at the viewer's end. Here is how to connect the two.

Live demo  ·  demo project  ·  video walkthrough

Why it needs configuring at all

Convai listens to Unreal's audio input, and on a streaming machine that input is empty. The browser has the viewer's voice; Pixel Streaming can carry it; the work is pointing Convai at that stream instead of at the local device that does not exist.

Part 1. The character Blueprint

  1. Open your character Blueprint and add a PixelStreamingAudio component, wiring up the audio-streaming nodes.

  2. In that component's settings, disable "Use Pixel Streaming Mic Input".

  3. Add an AudioInput node under the PixelStreamingAudio component.

  4. Under Edit → Project Settings → Convai, enter the API key from your Convai dashboard.

Step 2 is the counter-intuitive one. The setting called "Use Pixel Streaming Mic Input" is turned off — the explicit AudioInput node is what feeds Convai, and leaving both enabled has them competing for the same audio.

Part 2. On the platform

  1. Package and upload the project.

  2. Create a configuration for it, and enable Browser Microphone.

Both halves are required

The Blueprint work routes the audio inside Unreal; the configuration setting is what makes the browser capture it in the first place. With one but not the other, the character simply never hears anything.

When the character does not respond

Work through these in order — most reports are the first two.

  • The permission was denied. Click the lock icon in the address bar, then Site settings → Microphone → Allow, and refresh. See audio and microphone, where a blocked mic can stop the stream starting at all.
  • The prompt never appeared because pop-ups are blocked. Same menu: allow Pop-ups and redirects, then refresh.
  • The tab is muted. Right-click the browser tab and check "Mute site" is off — and check system volume.
  • The browser restricts it. Chrome, Edge and Firefox are the supported ones. Safari and some mobile browsers limit microphone access depending on version.
  • An old permission is cached. After changing any of the above, clear the cache and start a fresh session — the old decision can survive a reload.
