A Ready Player Me integration that works locally can fail when streamed, with the error "Failed to download a list of avatar templates." This is the fix.

What is happening

Ready Player Me fetches avatar templates over HTTPS at runtime. Unreal's default network settings verify the peer certificate on that request, and in the streaming environment that verification fails — so the request is refused and the app reports that it could not download the list.

Nothing is wrong with your integration or with Ready Player Me. It is a setting in your project that has to be changed before packaging.

The fix

  1. Open Config/DefaultEngine.ini in your project

  2. Add these two lines

    [/Script/Engine.NetworkSettings]
n.VerifyPeer=false

  3. Rebuild and repackage

    The setting is compiled into the build, so an existing package is not affected by editing the file — you need a new one.

  4. Upload the new build and test the integration

    Through the Control Panel, or from Unreal.

Understand what you are turning off. n.VerifyPeer=false stops your app checking the certificate of the servers it talks to — for all its network requests, not only Ready Player Me's. That is acceptable for a build whose network traffic you control and know. It is not something to leave on by habit in an app that talks to other services, or that handles anything sensitive.

This is a workaround, not a resolution

It has to be applied per project, by hand, and repeated for each app. If you maintain several, it belongs in whatever you use to set up a new project rather than being remembered each time.
