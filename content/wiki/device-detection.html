Your app runs on a server, so it cannot tell whether the person watching is on a desktop or a phone. This asks the browser and tells the app.

Everything Unreal knows about "the machine" is the streaming machine — always a Windows or Linux server with no touchscreen. The viewer might be on an iPad. Without asking, your app will happily show a right-click hint to someone who has no right button.

What this is worth doing for

Swapping the control scheme and the on-screen hints: touch gestures and larger hit areas on mobile, mouse and keyboard on desktop. It is the difference between an app that works on a phone and one that merely appears on it.

Asking

  1. Place an E3DS_PS_actor in the level.

  2. Call Request User Device Info.

The answer

The platform replies with a JSON message describing the viewer's device:

{
  "type": "takeUserDeviceInfo",
  "userDeviceInfo": {
    "os": {
      "name": "Windows",
      "short_name": "WIN",
      "version": "10",
      "platform": "x64",
      "family": "Windows"
    }
    // ... browser, engine and other details
  }
}

There is more in there — browser, rendering engine, and so on — but in practice you want os.name or os.short_name:

nameshort_name
WindowsWIN
macOSMAC
LinuxLIN
ChromeOSCHR
AndroidAND
iOSIOS

Reading it without parsing JSON

You can parse that yourself, or with a JSON plugin such as Json Utilities or VaRest. The simpler route is the plugin's own Detect User Device node, which does the parsing and hands back the two values most apps actually branch on: the OS name, and whether this is a touch device.

Branch on "is touch device", not on the OS name. A Windows tablet has a touchscreen and a Mac does not, so the OS is a poor proxy for the question you are really asking. Use the OS name for things that genuinely differ by platform — keyboard modifiers, say — and the touch flag for input.
