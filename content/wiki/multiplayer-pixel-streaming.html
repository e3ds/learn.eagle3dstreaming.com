Several people in one shared world, each watching from their own browser. That needs a second build — a dedicated server — alongside the game itself.

What makes it different

An ordinary streamed app gives every viewer their own private session. Two people opening the same link are in two separate copies of the world and cannot see each other. A multiplayer app adds a server that all the clients connect to, and that server is what makes them share a world.

You end up with two builds, not one

A server build that hosts the session and has no graphics, and a game build that players stream. Both come from the same project, both are uploaded, and they must stay in step — changing one and not the other is the most common way a working multiplayer app stops working.

The path

  1. Build the project — convert to C++, add a server module, configure maps and modes.
  2. Package both builds — server and game.
  3. Upload them — server first.
  4. Start the server and play.

Then, once that works, two things that make it practical:

  • Automatic server join — so players do not type an IP address.
  • Upload from the editor — so packaging and uploading both builds is one click.

This section covers dedicated servers. Unreal also supports listen servers, where one player's game acts as the host. Dedicated servers are what suits streaming, because no player's session has to stay open for everyone else's.
