Stream links, new versions, choosing which version runs, rolling back, and deleting things you no longer need.

Stream links

A stream link is the URL you share. Generate one from your app in the Control Panel, then attach a configuration to it — the settings belong to the link, not to the app, so one app can have several links behaving differently.

  • Copy the URL to share it.
  • Play App starts a session yourself, for testing.
  • Delete a link when it should stop working. Anyone holding a deleted link can no longer stream — which is the fastest way to revoke access you have already given out.

New versions

Use the update icon on the app, then upload the new ZIP. What happens next depends on a setting you chose earlier:

Version controlResult
OnA new version is added. The old one stays and can be selected.
OffThe new build replaces the old one, which is gone.

With version control on, you can select which version runs, and delete versions you no longer want. That combination is what makes an update reversible.

Rolling back

When a new build turns out to be broken, there are two ways back and they are not equally safe.

All plans

Re-upload the previous build

Get the old build — from the old Control Panel, or from your own S3 storage on Enterprise — and upload it as a new version. Slower, and it is a normal deployment with nothing unusual to go wrong.

Enterprise only

Rename versions on the shared drive

Delete the broken version on the VM and rename the previous one in its place — delete v10, rename v9 to v10. Fast, and entirely manual.

The manual route has no safety net. You are renaming directories on live infrastructure: a mistyped name or a wrong deletion takes the application down, and there is nothing to undo it with. Disable the "delete old version" feature first, or the build you are rolling back to may already be gone.

Use it when speed genuinely matters and someone competent is at the keyboard. Otherwise re-upload — slower is the correct trade when the alternative failure is an app that no longer exists.

The decision that makes rollback possible happens earlier

Both routes assume you still have the previous build. With version control off, uploads overwrite — so turn it on before you need it, not after.

Deleting an app

Deleting removes the application and its versions. Its stream links stop working. This is not reversible, and re-uploading produces a new application rather than restoring the old one — so any links you had shared stay dead.
