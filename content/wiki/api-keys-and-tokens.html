Two kinds of key, one kind of token, and a version-control switch. They live in the Developer section of the Control Panel.

The two keys are not interchangeable

Your API key can delete your app, or replace it with a different one. It is an account key, not a streaming key — anyone holding it can do those things to your account.

Use the Streaming API key for anything that reaches a browser. It exists precisely because the plain API key is too powerful to put in a web page, and support for using the plain key that way is being withdrawn.

API keyStreaming API key
Can delete or replace your appYesNo
Use in a web integrationNo — being withdrawnYes
Keep itServer-side onlyServer-side, and never longer than you must

If you have an existing integration using the plain API key, move it to the Streaming API key now rather than when support ends. The change is one value, and the current arrangement means a key with the power to delete your application is being handed to every visitor's browser.

The API key

One per account, found in the Developer section.

Generating a new one immediately invalidates the old one. Anything still using the previous key stops working at that moment — every app, every integration, every script. Rotate it deliberately, and know what will need updating before you press the button.

Tokens

A token authorises one streaming session. Single use, and it expires if it is not used within the time you set.

That is what makes tokens the right thing to give a browser: one expires harmlessly, where a leaked key does not. Generate them from the Token Generation tab, or from your server as part of an SDK integration.

Because a token is single use, restarting a stream needs a fresh one — reusing the previous token fails rather than reconnecting.

Version control

A switch, and the two behaviours are quite different.

Version controlUploading a new build
On Adds a version. Version 3 becomes version 4, and 3 remains.
Off Replaces what was there. The previous build is gone.
Turn it on before you need it

With it off there is nothing to roll back to — the previous build was overwritten, not archived. The moment you discover you want the old version is the moment it is too late to have kept it.
