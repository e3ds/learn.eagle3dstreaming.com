With the Server Scaling plugin, a client asks the platform which server to use and joins it on launch. No IP address, no port, no console.

Why the manual route does not survive contact with real players

A server's address is assigned when it starts, so it is different every time. Typing it into a console is fine while you are testing and impossible for a viewer — especially on a phone, where there is no console to open. This plugin is what turns a working multiplayer project into a usable one.

Before you start

A project that already has its server module, and an API key.

Step 1. Install the plugin

Download it from Fab or GitHub, and extract it into a Plugins folder at your project root — creating that folder if it is not there.

Open the project in the E3DS engine build, enable Pixel Streaming under Edit → Plugins, and restart.

Step 2. Configure the sample actor

  1. In the Content Drawer, go to Plugins → Multiplayer Server Scaling System Content → Samples and open BP_E3DSMPS_SampleActor.

  2. In the Details panel, under User Info, fill in four fields:

    FieldValue
    API KeyFrom API management in the Control Panel.
    Dedicated Server App NameThe name of your uploaded server app — for example MyProjectServer.
    Server VersionThe version, for example 1.
    Command Line1

  3. Compile and save.

The server app name has to match what you uploaded. It is how the plugin asks for the right server. A name that does not match returns nothing to join, and the client sits there apparently connecting — the same symptom as a server that is simply not running.

Step 3. Put the actor in the map

Drag BP_E3DSMPS_SampleActor into your level, then select it and confirm the Details panel shows the same values you set on the Blueprint.

Check the placed instance, not just the Blueprint. A placed actor keeps its own copies of these values, so an instance dropped into the level before you filled the fields in still carries the blanks. This is worth thirty seconds because the failure looks exactly like a wrong API key.

Then package and upload as usual

Package both builds and upload them. When a player opens the streaming URL now, the client finds its server and joins — including from a mobile browser, which the manual route could never support.
