Start a server, then bring players to it — from a browser, or from the desktop build while you are still testing.

Start the server

  1. In the Control Panel, go to Multiplayer Server Apps and open your uploaded server.

  2. Click START A SERVER.

Note the IP address and port

Starting a server allocates it an address, and that is what clients connect to. It is assigned at start time, so it is not something you can hard-code once — which is exactly the problem automatic join exists to remove.

Play from the browser

  1. Open your uploaded game app and create a streaming URL for it.

  2. Open that URL on two devices, or in two browser windows.

  3. Press play on each, then Join To Server.

This works from a mobile browser too — there is nothing desktop-specific about a streamed multiplayer client.

Play from the desktop build, while testing

Before uploading the game, you can point the local build at the running server and check the multiplayer behaviour itself.

  1. Start a server in the Control Panel, as above, and note its address and port.

  2. Run the packaged game application on your machine.

  3. Press ` (backtick) to open the console and connect:

    open 172.7.191.81:28889

  4. Do the same in a second instance, so there are two players.

What you should see, either way

Two avatars in one world, each moving when its own player moves. If each window shows only one player, they are in separate sessions — the join did not happen, whatever the connection appeared to do.

Test against a local server before a hosted one. Running both on your own machine removes the upload, the platform and the network from the picture, so a failure there is unambiguously in the project.
