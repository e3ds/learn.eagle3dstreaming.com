Unreal-side questions that come up repeatedly when preparing an app for streaming: which build configuration, how to get logs out of it, how to reach files you packaged, and how your app should talk to the page.

Choosing a build configuration

Unreal offers several, and the choice is a trade between how fast it runs and how much it can tell you when something goes wrong.

ConfigurationUse it
Development While building and diagnosing. Slower, and it keeps the logging and tooling you need to find a fault.
Shipping For release. Fastest, smallest — and it strips out the logging, which is the trade.

Logs cannot be added to a Shipping build after it is packaged. They are compiled out, not switched off. Getting them back means building from Unreal's source engine from GitHub with modified engine code, switching your project to that engine and regenerating the solution — which is a day's work, not a setting.

So: while an app is still being diagnosed, package Development. Move to Shipping when you no longer expect to need the logs, not before.

Talking to the page: VaRest or Pixel Streaming Input

Both plugins can handle the JSON that arrives from a web page, which is why the choice comes up at all.

Prefer this

Pixel Streaming Input

Epic's own, built for exactly this, and already required for streaming. Nothing extra to install and nothing extra to keep working across engine upgrades.

VaRest

A general-purpose JSON plugin. Worth it only if you are already using it for other work in the project — then it is one JSON approach instead of two.

Sending in the other direction is the same either way: the Send Pixel Streaming Response node, with a Pixel Streaming Input component on the actor. See sending and receiving data for the page's half.

Files you packaged, and how to reach them

Non-asset files — videos, text, configuration — need to be included in the package deliberately, and then found at runtime.

Use relative paths, not absolute ones. An absolute path is correct on your machine and wrong on ours: the app runs from a different directory on a streaming machine, so a path that begins with your drive letter cannot resolve. This is a common cause of an app that works locally and fails as soon as it streams.

The mouse cursor

A streamed app shows the browser's cursor as well as its own, which is disorienting enough that people report it as lag. The fix is to hide the app's cursor — a custom cursor image with zero alpha — so only the browser's remains. Optimising your app covers the settings.

Anti-aliasing

Anti-aliasing smooths the jagged edges that appear when curves are drawn on a rectangular grid of pixels. It costs GPU time on every frame, and in a stream it competes with the encoder for the same GPU.

At a streamed resolution the difference is smaller than it is on a desktop monitor, because video compression softens edges anyway. If you are short of frame rate, this is a cheaper thing to reduce than most.
