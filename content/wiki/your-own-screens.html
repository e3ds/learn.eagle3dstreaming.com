A wait and a failure are the two moments your stream looks least like your product. Both are replaceable: the platform tells your page what is happening, and you decide what appears. With the Web SDK that is a callback; with an iframe it is a postMessage event.

Read this before you design any of them

None of these callbacks can cancel or delay what is happening. They tell you; they do not let you intervene. So design every screen around the session already being over — offer a way to start a new one, rather than anything that implies the old one might come back.

A "reconnecting…" spinner on a session that has ended is worse than a blunt message, because it asks the viewer to wait for something that will never arrive.

A loading screen

Two events bracket the wait, and the pattern is simply show-then-hide.

EventWhat to do
onConfigAcquire Show your loading screen — the session is preparing.
onDataChannelOpen Hide it — the stream is live.
 
e3ds_controller.callbacks.onConfigAcquire = function () {
  document.getElementById("myLoadingScreen").style.display = "flex";
};

e3ds_controller.callbacks.onDataChannelOpen = function () {
  document.getElementById("myLoadingScreen").style.display = "none";
};

For a progress bar rather than a static image, the three onReceivingApp…Progress callbacks report acquiring, preparing and starting as they happen — see the reference. They are three separate stages, not one bar filling up, and a progress bar that pretends otherwise will stall at odd percentages.

A hosted image needs the direct URL

The one ending in .png or .jpg — not the share page the host shows you. A share page will not load as an image and the failure is silent: an empty loading screen rather than an error.

A session-expired screen

By default the platform shows its own "session expired" page. To show yours instead: 

e3ds_controller.callbacks.onSessionExpired = function () {
  document.getElementById("mySessionEnded").style.display = "flex";
};

With an iframe, keep a full-screen overlay hidden in your page and reveal it when the frame reports the session has ended. Because the overlay is yours, you can put a start a new session button on it — which the default screen does not offer, and which is the single most useful thing to add.

onSessionExpired covers the time limit and nothing else

It does not fire for a crash, an idle timeout, a wrong password or an expired link. If you want one screen for every way a session can end, build it on onSessionEnding instead — that one fires for all of them and carries a line of text explaining which.

Every message a session can end with lists what that text can say.

A message for a crash, and only a crash

Showing "something went wrong" when a session simply reached its time limit is worse than showing nothing. Reacting to a genuine crash needs two events together, because neither is sufficient alone — the reasoning, and the flag pattern that solves it, are on the session-end page.

The short version: onStreamerDisconnected fires only for a crash and carries no text; onSessionEnding fires for every ending and carries the message. Set a flag on the first, read it on the second.
