Testing a VR build locally has one requirement the others do not: the page must be served over HTTPS, because browsers will not hand WebXR to an insecure page.

Before you start

A packaged Windows build of a VR-configured project, and a headset on the same network as the machine. Everything up to the last step happens on the computer; only the final step happens in the headset.

Step 1. Download the signalling server

<Packaged Folder>\Windows\<YourProject>\Samples\PixelStreaming\WebServers\get_ps_servers.bat

Run it, let the terminal finish downloading, and let it close itself.

Step 2. Turn on HTTPS

In the SignalingWebServer folder, open config.json and set: 

"useHttps": true
This step is not optional for VR

WebXR — the browser API that puts the stream into the headset — is only available on a secure page. Over plain HTTP the stream still works as a flat picture, and the XR button simply never appears. If you get that far and cannot find the button, this is why.

Step 3. Add the certificate

HTTPS needs a certificate. Download the certificate ZIP and extract it into the SignalingWebServer folder.

The headset browser will warn you about this certificate. It is self-signed and not issued for your machine's address, so that warning is expected. Accept it and continue — this is a local test, not something you would put in front of a viewer.

Step 4. Start the signalling server

<...>\SignalingWebServer\platform_scripts\cmd\run_local.bat

On newer Unreal versions this is Start.bat. Leave the terminal open.

Step 5. Launch the app with VR arguments

Make a shortcut to your .exe, open Properties, and append to the Target field: 

-log -AudioMixer -PixelStreamingIP=localhost -PixelStreamingPort=8888 -RenderOffScreen -AllowPixelStreamingCommands -PixelStreamingEnableHMD -ResX=1920 -ResY=1080

-PixelStreamingEnableHMD is what makes it a VR stream. The resolution flags matter too:

"Encoder pending resolution exceeds device max capabilities" means the -ResX=1920 -ResY=1080 flags are missing. A VR app renders two eyes, so the frame it hands the encoder is far wider than a flat app's — without a cap it exceeds what the encoder will accept and the stream never starts.

Run the shortcut, and leave its terminal open too.

Step 6. Open it in the headset

  1. On the computer, run ipconfig and copy the IPv4 address.

  2. In the headset's browser, go to that address over HTTPS — for example https://192.168.1.25. Accept the certificate warning.

  3. Press the XR button to enter immersive mode.

You should be inside your app

If instead you see a plain server page with no stream, the build was packaged without Pixel Streaming enabled — the same failure as the flat local test. If you see the stream but no XR button, HTTPS is not actually on.
