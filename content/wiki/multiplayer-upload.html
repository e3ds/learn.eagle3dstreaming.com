Both builds go to the Control Panel, but to different places: the server to Multiplayer Server Apps, the game to Applications like any other app.

Server and game must be packaged from the same state of the project. They speak to each other, and a game built after a change the server does not have will connect and then behave incorrectly. Upload them as a pair, every time — not just when the change looked server-related.

The server

  1. In the folder you packaged the server into, open WindowsServer, select everything in it, and ZIP it.

  2. In the Control Panel, go to Multiplayer Server Apps — not the ordinary Applications list.

  3. Choose Add Applications and browse to the ZIP.

  4. Name it exactly as the .exe at the root of the ZIP.

  5. Upload.

The name must match the executable. That is how the platform finds what to launch. A mismatched name uploads without complaint and then fails to start a server, with nothing in the Control Panel connecting the two facts.

The game

Same shape, ordinary destination.

  1. In the folder you packaged the game into, open Windows, select everything, and ZIP it.

  2. In the Control Panel, choose Add Application and browse to that ZIP.

  3. Name it to match the .exe at the root of the ZIP, and upload.

It then goes through the six upload phases like any other app.
