The SDK puts the stream directly in your page and hands you the session in JavaScript — you start it, drive it and end it. It handles the token, the authentication, the connection and the player.

The old SDK no longer works. Our streaming infrastructure was upgraded and the previous SDK is not compatible with it. Integrations still using it have stopped streaming, not degraded.

Nothing changes in your Unreal application. The work is entirely on the web side, which makes the move smaller than it sounds.

Before you begin

An app uploaded and streaming from the Control Panel; your Streaming API key — read the warning below, because there is more than one kind of key; and your username plus the app and configuration names exactly as the Control Panel shows them, capitalisation included.

Not sure yet? Play with it first

The Web SDK demo manual walks through the running demo control by control — what each one does and which SDK call is behind it — with nothing to download and no key to enter. Come back here when you want the code.

Or just open it, running, right now

demo-sdk.eaglepixelstreaming.com is this sample deployed. It streams a real application with no key, no clone and no setup, so you can see what you are about to download before you download it.

Its address is deliberate. The page is on eaglepixelstreaming.com; the platform it streams from is connector.eagle3dstreaming.com. Different origins — which is the answer to "will this work on my own domain?" Yes, and that demo is the proof rather than the promise.

Start from the sample, not from scratch

Download the demo project, get it streaming your app, and only then move the pieces into your real application. It is a working integration, so anything that fails is your configuration rather than your code — a far smaller thing to debug than both at once.

There is a live version you can open before downloading anything.

What is in it

sdk/
├── index.html                     the page itself
├── css/style.css                  styles the demo's buttons only
└── scripts/
    ├── sdk-config.js                  the only file you must edit
    ├── sdk-token.js           gets a token, starts the session
    ├── sdk-callbacks.js        every callback, documented
    ├── demo-controls.js           the demo's buttons
    └── dist/e3dsCore.min_ns.js    the SDK itself (generated, never edit)

Carry sdk-config.js, sdk-token.js, sdk-callbacks.js and dist/ into your own project. index.html and demo-controls.js are references rather than things to copy.

Configure it

You need a Streaming API key for this step

It is the first value in the file. Streaming API key and tokens — what it is, why it is not the account API key, and where to get one. Two minutes, then come back here.

Everything you need to change is in scripts/sdk-config.js. It is the only file you have to edit to get the demo running against your own app.

SettingSet it to
STREAMING_API_KEYYour Streaming API key.
clientUserNameIdentifies the person watching. In a real integration, your own logged-in user's id.
tokenExpiryMsHow long the token stays valid, in milliseconds. 60000 is a good default — it only has to last long enough to start the session.
application.domainThe connector your account was given, for example connector.eagle3dstreaming.com.
application.userNameThe account that owns the app.
application.appNameThe app's name, exactly as the Control Panel shows it.
application.configurationNameWhich stored configuration to launch.
application.versionA specific version, or "latest".
configurationToOverridePer-session overrides of that stored configuration. Applies to this session only and does not change the saved one; leave it empty to use the Control Panel's settings as they are.

There are two kinds of API key, and only one works here. Use the Streaming API key. The other looks identical, is for a different purpose, and fails at token generation with nothing that says "wrong sort of key".

Enterprise plans use a different domain. Replace connector.eagle3dstreaming.com with the custom domain provided to you. If you are not sure which applies, ask support rather than guessing — a wrong domain fails at connection time and looks like a network fault.

Serving it

Opening index.html straight from disk does work — the token endpoint sends Access-Control-Allow-Origin: *, which accepts the null origin a file:// page has. It is the quickest way to try the demo. 

python -m http.server 8000     # or:  npx serve .     # or:  php -S localhost:8000
Serve it anyway, once you are past the first look

Not because file:// is blocked, but because it works only for as long as that endpoint accepts any origin — a server-side policy you do not control and would not be told about. Serving over http:// is how your real integration will run, so a problem that only appears there is better found now than after you have moved the files into your own application.

Script order is not arbitrary

<script defer src="./scripts/dist/e3dsCore.min_ns.js"></script>
<script defer src="./scripts/sdk-config.js"></script>
<script defer src="./scripts/sdk-callbacks.js"></script>
<script defer src="./scripts/demo-controls.js"></script>
<script defer src="./scripts/sdk-token.js"></script>
Two rules, and breaking one of them fails silently

The SDK loads first, because everything after it refers to e3ds_controller — move it and you get e3ds_controller is not defined, which at least says so. sdk-token.js loads last, because it starts the stream: a callback registered after the stream has started has already missed whatever fired first. That one produces no error at all — just callbacks that never run.

Your page also needs a <div id="playerUI"></div> for the player to render into.

One thing to know before you go live

The demo keeps your API key in sdk-config.js, which means every visitor to the page can read it. That is fine for what you are doing now — trying it out, an internal demo, development against your own app.

It is not fine on a public site. The key does not expire, and anyone who reads it can start sessions billed to your account. Before you put this on a page the public can reach, move the key to a server: keeping your API key off the browser. It is one change to one function, and nothing else in your integration moves.

Moving it into your own application

Once the sample streams your app: load the SDK, call e3ds_controller.main() with the token data, and build your interface when onDataChannelOpen fires. From there, send and receive data and control the stream.
