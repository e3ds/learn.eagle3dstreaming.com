A phone has no keyboard until something asks for one. When a text field in your streamed app takes focus, the device's own keyboard appears — on Unreal 5.6 and above.

Nothing to enable

Focus a text input in the streamed app and the keyboard comes up. Typing is captured and applied in real time. No plugin, no configuration, no code.

Unreal version support

UnrealWorksWhat happens on the older ones
5.7Yes—
5.6Yes—
5.5NoThe keyboard appears, then the app crashes when you type.
5.4NoThe keyboard appears, then the app crashes when you type.
5.3NoThe keyboard appears and accepts input, but the field never updates.

On 5.4 and 5.5 this is not a cosmetic problem. Typing crashes the application, which ends the viewer's session. If your app takes text input and your audience is on phones, upgrading to 5.6 is the fix — there is no workaround on the older versions.

If something is wrong

SymptomCauseFix

Keyboard is cut off or covers the fieldMobile viewport and scalingPut the stream in fullscreen, which gives the browser a viewport it can resize around.
Typing feels delayedNetwork, or the app is rendering heavilyThe keystrokes are travelling to the server and back like any other input — see network requirements.

A connected physical keyboard wins. On a tablet with a keyboard case, the on-screen keyboard will not appear — which is correct behaviour, and worth knowing before you conclude it is broken. Appearance also varies a little between browsers and devices, since it is the device's keyboard, not ours.
