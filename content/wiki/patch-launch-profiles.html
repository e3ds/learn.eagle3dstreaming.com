Patching needs two custom launch profiles in Unreal's Project Launcher: one that produces the base build, and one that produces patches against it.

Where these live

Platforms → Project Launcher → Add a Custom Launch Profile. You will make two, and keep both — the base profile is not a one-off.

"Create a release version" is what makes patching possible later. It records the state of this build so a future patch can be computed as the difference from it. A base packaged without it cannot be patched, and you will not find that out until you try to build the patch.

The two version fields are the whole mechanism

Based on says which build to compare against; new release version names what you are producing. Point the patch at the wrong base and you get a patch file that appears fine and does not work against the build you actually shipped.

Rules that bite later

  • Keep the base .pak. The app will not run without it.
  • Upload the base first, then patches in order. Higher-numbered patches override lower ones, so sequence is meaning, not tidiness.
  • Name them consistently — testPatch3-Windows_0_P.pak, testPatch3-Windows_1_P.pak, and so on.
  • Keep old patch files. Removing a patch reverts the app to the previous version, which is a useful escape hatch only if you still have the files.
