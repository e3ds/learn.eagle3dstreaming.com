A stream can end for a dozen reasons, and every one of them arrives at your page the same way: a message from the Eagle 3D Streaming system, delivered to one callback. This is what those messages are, where each one comes from, and what to do with them.

These come from us, not from Unreal. Nothing here originates in your application, and none of it travels over the data channel. They are generated by our front end and our back end — the signalling server, the Control Panel, the session accounting — and delivered to your page even when your app has already stopped running. That is the point: they are how you find out why it stopped.

How you receive them

e3ds_controller.callbacks.onRedirectingWithMessage = function (message) {
    showMyEndScreen(message);   // one screen, every reason below
};

Assign it before the stream starts. There is exactly one callback for this — onStreamerDisconnected and onSessionExpired each cover one narrow case and neither is a substitute.

Why one callback rather than one per reason

Because the list below grows. A page built on onRedirectingWithMessage handles a new ending on the day it ships, without you touching anything. A page with a branch per known reason shows nothing at all for the one it has never seen — and that is the case a customer reports to you rather than one you find yourself.

Someone ended it deliberately

You kicked the viewer

The Control Panel lists every session running on your account and lets you end any of them. This is the message a viewer gets when you do.

A moment later, that viewer's page receives: 

You have been kicked out
This is the one you can trigger on demand, so test with it

Open your own integration, find the session in Utilities, press Kick Player, and watch your end-of-session screen appear from a real event. That is worth far more than calling the callback by hand, because it exercises the whole path — and it is the only ending you can produce reliably, at will, in a few seconds.

A meeting host closed the meeting

In a meeting, the host's session is the one that matters. When the host leaves, every guest is ended with: 

Host's Streaming Closed

Time ran out

Two different limits, two different messages, and it is worth knowing which is which because only one of them is about the viewer being idle.

SettingMessageWhat it means
Maximum session length Session lasted for <duration>. Session expired. The session hit the ceiling you configured. Set an hour, and this arrives after an hour of perfectly normal use.
Link expiry Url Expired The link itself had a lifetime and it passed. The session never started, or started and the link is no longer valid for another.

The duration is spliced into the text. So the message is never twice the same, which is the clearest possible argument against matching on it. Show it — a viewer told "your session lasted 58 minutes" understands immediately what happened; a viewer shown "Session expired" alone often assumes something broke.

The application stopped

MessageWhat happened
App CrashedYour Unreal application stopped unexpectedly. This is about your build, not the platform — see optimise your app and the hardware budget.
The machine "<name>" is not currently online…A named machine was requested and it is switched off, or the name is wrong. Relevant if you use your own GPU.
The requested exe launcher is currently busy. Please try again later.Every machine that could run your app is occupied. Not an error in your integration — a capacity condition, and a retry later usually succeeds.

The account cannot stream

MessageWhat happened
User <name> not found. Please register from…No such account. Almost always a typo in userName.
User <name> does not have an active subscription…The account has no plan.
User <name> subscription expired. Please renew…The plan lapsed — see plans and billing.
User <name> has reached maxUserLimit of <n>Your concurrent-user limit is full. Every slot is in use by someone else on your account.

These four are about you, and they are shown to your viewer. Somebody who came to look at your product is told that your subscription expired, or is shown your username and an internal limit name. They can do nothing about any of it, and it is not information you would choose to give them. On a public integration this is the strongest single reason to replace the default screen: catch the message, log it for yourself, and show the visitor something written from where they are sitting.

Access was refused

MessageWhat happened
You did not enter the correct password. Please refresh the page.A password-protected link, answered wrongly.
Token verification: <reason>The session token did not verify — expired, malformed, or issued for a different app. See token handling.
Your application is running on UE4.27… Please upgrade to UE5.1 or later.The build is on an unsupported engine version. See supported versions.

What to do with the message

Show it. Do not parse it.

Several of these carry a duration, a machine name, a username or a limit spliced into the text, so the exact string is often unique to that one session. The wording also changes, and new endings are added. Code that branches on the text will break on a rewording nobody considered breaking. If you need to react differently to different endings, ask us for a machine-readable code rather than matching strings.

Write it with textContent

document.getElementById("myEndMessage").textContent = message;   // yes
document.getElementById("myEndMessage").innerHTML = message;     // no

The text comes from the platform and is meant to be read, not executed. The sample in stream-callbacks.js uses textContent for this reason.

You cannot cancel it

The session is already over when you are told

onRedirectingWithMessage is a notification, not a veto. By the time it fires the machine has been released. Design the screen around that — offer a way to start a new session if that makes sense for your app, but do not build anything that assumes the current one can be saved.

A shape that handles all of them

e3ds_controller.callbacks.onRedirectingWithMessage = function (message) {
    // 1. Keep it for yourself. Several of these describe an account or
    //    capacity problem that you, not the viewer, need to act on.
    sendToMyLogging({ event: "session_ended", message: message });

    // 2. Show the viewer something. The platform's wording is a reasonable
    //    default; substitute your own where you can do better.
    myEndScreen.querySelector(".detail").textContent = message;
    myEndScreen.style.display = "flex";

    // 3. Offer the only useful action there is.
    myEndScreen.querySelector("button").onclick = () => location.reload();
};

This list will grow

New endings arrive as the platform changes, through the same callback, with wording you have not seen before. This page is kept up to date; a page that shows whatever it is given needs no update at all.
