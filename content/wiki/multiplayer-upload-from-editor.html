With the Automation Tools plugin, one click packages both builds, compresses them, and uploads them — instead of two packaging runs, two ZIPs and two browser uploads.

Before you start

The Automation Tools plugin extracted into your project's Plugins folder, Pixel Streaming enabled, 7-Zip installed, and the E3DS engine build — the binary Launcher engine cannot produce a server, with or without this plugin.

Configure it

Edit → Project Settings → Plugins → E3DS Automation Tools Settings.

SettingWhat to put in it
Path to E3DS ExecutableThe EL_AT.exe you get from the Download E3DS Automation Tool Executable button on this same page.
Path to 7Z.exeYour 7-Zip installation.
API KeyGet E3DS API Key generates one; paste it back into the field. Sign in first if prompted.
E3DS Streaming App NameLetters and numbers only — no dots, no spaces.
Packaging ModeDevelopment or Shipping. See below.
Do Dedicated Server BuildEnable this. Without it you get only the game build.
E3DS Dedicated Server App NameThe same name you used for the server application.
Launch Streaming App URL on CompletionOpens the stream in your browser as soon as the upload finishes.

Reusing an app name creates a new version rather than a second app. That is usually what you want when iterating — and it means a typo in the name silently creates a separate application instead of updating the one you meant.

Development or Shipping

Choose Development the first few times

Development packaging is slower but shows the output log while it runs; Shipping is faster and shows nothing. When something goes wrong, that log is the only thing that tells you what — so pay the time until the pipeline is known to work, then switch.

Run it

Click the E3DS icon in the toolbar and choose Launch E3DS Automation Tool. A command prompt opens; packaging runs, then upload. After a few minutes it reports both the server app and the game app uploaded.

Package manually once before relying on this. The plugin hides packaging behind one click, which is the point — and also means a packaging error arrives with much less context. Doing it by hand once proves the project itself is sound, so anything that fails afterwards is the pipeline rather than the build.

If the upload fails

  • Not enough disk space where the packaged folder lives — two builds plus their archives need room.
  • A setting above is wrong — most often a path or the API key.
  • You are on the binary engine from the Epic Launcher, which cannot build a dedicated server at all.
  • Visual Studio is not properly set up for Unreal.
Start the server and play →

Both builds are uploaded — now get players into them.
