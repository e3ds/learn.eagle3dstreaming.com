Same machine running the app and the signalling server — but watched from a phone, tablet or second computer on the same network.

This is the test worth doing before you promise anyone the app works on mobile. Touch input, screen size and the on-screen keyboard all behave differently, and none of that shows up when you test in a desktop tab.

Before you start

The local test already working, and both devices on the same network. If the local test does not work, this one cannot.

  1. Start your app from the shortcut with the streaming arguments, and leave its terminal open.

  2. Run run_local.bat (or Start.bat) from the signalling server folder, and leave that terminal open too.

  3. In a command prompt, run ipconfig and find the IPv4 Address of the machine.

  4. On the other device, open a browser and go to that address.

  5. Press CLICK TO START.

What this tells you that the local test does not

Whether your interface is usable at that screen size, whether touch reaches the controls, and whether text fields bring up the on-screen keyboard. It does not tell you anything about real-world latency — everything here is on your own network.

If the address does not load, it is the network, not the app. The usual causes are the two devices being on different networks (a guest Wi-Fi, or one on mobile data), or Windows Firewall blocking the port. Confirm the same address still works in a browser on the host machine first — that separates the two possibilities in one step.
